# Спецификация: сервис школьных обращений (учебная копия)

Единая спецификация для всех уровней.

- Ученик подаёт обращение без регистрации: категория (техника, кабинет, столовая, идея, другое), текст 1-1000 символов, кабинет (необязательно). Имя не нужно.
- После подачи ученик видит код обращения: 6 символов из алфавита A-Z и 2-9 без O и I, генерация через crypto.randomInt, при коллизии повтор.
- Страница статуса по коду показывает только категорию, статус, публичный ответ модератора и даты. Текст обращения и кабинет там не показываются.
- Статусы: new -> in_progress, new -> rejected, in_progress -> resolved, in_progress -> rejected. Из resolved и rejected переходов нет. При rejected причина обязательна: непустая после trim. Причина и ответ показываются ученику.
- Лимит: не больше 3 обращений за скользящие 60 минут с одного устройства. Устройство определяется httpOnly cookie device_id, которую сервер выдаёт при первом заходе. Лимит проверяется на сервере.
- Модератор входит по паролю из переменной окружения MODERATOR_PASSWORD, получает подписанную httpOnly cookie-сессию (SESSION_SECRET), видит список обращений (новые сверху), фильтрует по статусу, меняет статус и пишет публичный ответ. Все модераторские API-роуты проверяют сессию на сервере.

## Схема статусов

```
new ──► in_progress ──► resolved
 │           │
 └──► rejected ◄┘
```

`resolved` и `rejected` финальные.
