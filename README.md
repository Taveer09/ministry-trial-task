# Школьные обращения — учебная копия

Учебная копия сервиса школьных обращений для вступительного кейса министерства цифровизации школьного совета.
Настоящий сервис работает отдельно, эта копия в прод не идёт. Все данные только тестовые: ни реальных имён, ни реальных кабинетов.

Спецификация сервиса: [docs/SPEC.md](docs/SPEC.md).

## Стек

Next.js (App Router) + TypeScript (strict) + Tailwind + SQLite (встроенный в Node.js модуль `node:sqlite`, без нативной сборки) + vitest. Внешних сервисов и ключей нет.

## Как запустить

Нужен Node.js 22.13 или новее.

```bash
npm i
cp .env.example .env.local
npm run seed
npm run dev
```

Открой http://localhost:3000. Вход модератора: http://localhost:3000/moderator, пароль из `.env.local`.

Тесты, линтер, типы и сборка:

```bash
npm test
npm run lint
npm run typecheck
npm run build
```

## Структура

- `src/lib` — вся логика чистыми функциями: код обращения, валидация, переходы статусов, лимит, сессия, работа с БД.
- `src/app/api` — тонкие route handlers.
- `src/app` — страницы: `/` (подача), `/status` (статус по коду), `/moderator/login`, `/moderator`.
- `src/proxy.ts` — выдаёт cookie `device_id` при первом заходе.
- `scripts/seed.ts` — 10 тестовых обращений.
- `tests` — тесты vitest.

## Задание уровня C

1. Сделай fork, запусти проект.
2. В проекте 3 бага разной тяжести: один виден сразу, один на крайнем случае, один про безопасность. Найди их сам. Каждый баг: отдельный Issue (шаги воспроизведения, ожидал, получил, причина).
3. На каждый баг отдельный Pull Request из отдельной ветки, связанный с Issue (`Fixes #N`). В описании PR: что было, что изменил, как проверил. Всё в одном PR склеенное не принимается.
4. Одна фича в отдельном PR: фильтр по категории в списке модератора (UI и API) плюс один тест или явная ручная проверка в описании.
5. В README своего форка добавь раздел «Что я делал сам, а что ИИ».
